# Contributing

Team: Redon, Rinor, Granit, and Leanda.

1. Use your own GitHub account and your own Git author identity.
2. Pull the latest changes before starting a task.
3. Use a short, descriptive branch name for your work.
4. Commit changes with messages that explain what changed.
5. Open a pull request for another team member to review when practical.
6. Update affected UML sources and diagrams when the design changes.

Commit only work you actually contributed. Do not use another teammate's identity or create commits merely to suggest participation.

## Documentation

- The Part 1 report is in `docs/`.
- Editable PlantUML diagrams and their SVG exports are in `docs/uml/`.
- After changing a `.puml` file, regenerate its corresponding diagram and keep the report consistent when the change affects the submitted design.

## Project setup

Build, database setup, and test commands will be added when the application is implemented. Keep passwords, tokens, local environment files, and database credentials out of commits.
